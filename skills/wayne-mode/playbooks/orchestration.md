# 多 Agent 协同交付

拆解大任务、多模型并行开发、跨模型对抗审查或多 PR 协同交付时，先读 [standard-multi-agent-delivery](../../standard-multi-agent-delivery/SKILL.md)。它定义拆分边界、worktree 拓扑、异构模型路由和对抗审查门禁；静态检查与行为证据见 [quality](quality.md)，提交与评审分级见 `standard-dev-workflow`。

## 执行

1. **判拓扑与拆切片。** 先看当前分支和工作区状态，在「主干扇出 / 分支内回流 / 栈式扩展 / 单 Owner 直做」中选定拓扑；分支内回流先将未提交改动存为 checkpoint commit。按用户操作可见的端到端行为拆垂直切片，禁止按技术层横切；明确每片的文件所有权、共享契约与风险等级（`Low` / `Medium` / `High`）。完成条件：每个子任务都能说清可观测的用户结果，且边界无重叠写冲突。
2. **定路由与派开发。** 读取本机模型配置并核对当前可用模型，按执行型与判断型分层派发到独立 worktree（单 Owner 模式留在当前 worktree）。完成条件：每个子任务带齐目标、非目标、契约、文件边界和验收命令。
3. **跑初审与对抗审查。** 总控先做范围、契约、验证与跨切片冲突初审；通过后按风险等级从跨家族有序候选池新起独立对抗审查（`Low` 0 席、`Medium` 1 席、`High` 2 席不同家族）。仅保留有运行实证的 `[Blocker]` / `[Major]`，修复后新起干净复审，最多 2 轮熔断升级人工。完成条件：无未解决阻塞项。
4. **整体验证与收口。** 将通过审查的切片回流当前特性分支，或按独立/栈式策略提 PR。所有切片集成后，按 [quality](quality.md) 从真实入口跑通跨切片端到端主流程，确认 CI 全绿且 `HEAD` 与验证结论一致后再合入。完成条件：用户主流程实测通过，交付报告列出各切片状态、模型配对、审查结论与未验证项。
